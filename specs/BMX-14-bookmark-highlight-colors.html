Tweak the highlight colors for bookmark items and URLs

A refinement spec for bookmark-express-v3: promote the search-hit and selected-row colors to a complete, per-theme, per-field token set, then pick the actual values in the interactive lab below before anything is committed.

Ticket: BMX-14 Phase: refinement Target: bookmark-express-v3 (Svelte + TS, MV3) Type: visual / CSS token change Date: 2026-07-26
How to use this document. §1–§4 are the spec: what is wrong today, and the exact token model and code changes that fix it. §5 is a live lab — open this file in a browser, drag the color pickers, and watch real popup mock-ups (modern light, modern dark, classic) update. The lab is what the values were chosen in; §5.1 records the signed-off result, which is what the build session commits verbatim. Nothing in the extension has been changed by this document.

1. TL;DR

Two colors do all the highlighting work in v3 today, and both are under-specified:

  • The search-hit background (the swatch behind matched text) — --search-hit-bg: yellow in the classic look, --highlight in the modern look.
  • The selected-row background — --selected-bg: #c2ffba in classic, --selected in modern.

The gaps: the ink color on a hit is hard-coded (modern) or inherited by accident (classic, where a URL hit lands as gray-on-yellow); titles and URLs cannot be tuned apart, though a URL hit wants to be quieter than a title hit; and the classic tokens have no dark variant at all.

The change: expand the two tokens into a five-token family per surface — hit background, hit ink, URL hit background, URL hit ink, selected row — with the URL pair falling back to the title pair when unset, so splitting them stays purely additive. Values were chosen in the lab (§5); the signed-off set is §5.1 — four colours move, the URL split is deliberately not taken this time.

v3 renders one of two looks from the same controller (src/App.svelte): the modern command-palette popup and the original classic list. They do not share highlight styling, so the change lands in two places.

This spec keeps each convention where it is rather than unifying them — see §8.

3. What's actually wrong

  • URL hits are the worst case and nobody tuned them. In classic, the URL line is color: gray; a hit inside it paints yellow behind that gray — the lowest-contrast text in the popup sitting on the loudest background. In modern the URL is var(--sub) but a hit forcibly switches it to near-black on amber, so the URL line changes weight mid-string.
  • The hit ink is not a token. oklch(0.15 0 0) is written directly into modern's .search-hit, so it cannot differ between light and dark even though the backgrounds do, and it cannot be tuned without editing a rule.
  • Titles and URLs share one color. There is no way to make a URL hit quieter than a title hit, which is the most likely thing to want here.
  • Hits inside a selected row are an untested combination. A hit swatch is drawn over --selected, not over the popup background, and the two were chosen independently (amber hits, green selection). The lab below always renders one selected row so this pairing is judged, not assumed.
  • Classic has no dark story. yellow and #c2ffba are emitted regardless of scheme, while the surrounding classic chrome uses system colors (Canvas, GrayText) that do flip. Deciding this is in scope; see the open question in §8.

4. The change

4.1 Token model

Each surface gets the same five roles. The URL pair is optional: components read it with a fallback, so leaving it undefined reproduces today's "URL looks like a title" behavior exactly.

RoleClassic (app.css :root)Modern (ModernView.svelte, per theme)Status
Hit background (title)--search-hit-bg--highlightexists
Hit ink (title)--search-hit-fg--highlight-fgnew
Hit background (URL)--search-hit-url-bg--highlight-urlnew, optional
Hit ink (URL)--search-hit-url-fg--highlight-url-fgnew, optional
Selected row--selected-bg--selectedexists

4.2 Code changes

components/Highlighted.svelte (classic) gains a kind prop so a URL hit can be styled apart from a title hit. Default 'title' keeps every existing call site working.

let { text, query, kind = 'title' }:
    { text: string; query: string; kind?: 'title' | 'url' } = $props()

<span class="search-hit" class:url={kind === 'url'}>{segment.text}</span>

.search-hit {
    background-color: var(--search-hit-bg);
    color: var(--search-hit-fg, inherit);
}
.search-hit.url {
    background-color: var(--search-hit-url-bg, var(--search-hit-bg));
    color: var(--search-hit-url-fg, var(--search-hit-fg, inherit));
}

components/Results.svelte passes the kind on the URL instance only: <Highlighted text={result.url} {query} kind="url" />.

components/ModernView.svelte takes the same treatment inside its own highlighted snippet, which is already parameterised by text:

{#snippet highlighted(text: string, kind: 'title' | 'url')}…
    <span class="search-hit" class:url={kind === 'url'}>{seg.text}</span>…{/snippet}

{@render highlighted(result.title, 'title')}
{@render highlighted(result.url, 'url')}

.search-hit {
    background: var(--highlight);
    color: var(--highlight-fg);
    border-radius: 2px;
    -webkit-box-decoration-break: clone;
    box-decoration-break: clone;
}
.search-hit.url {
    background: var(--highlight-url, var(--highlight));
    color: var(--highlight-url-fg, var(--highlight-fg));
}

The hard-coded color: oklch(0.15 0 0) is replaced by --highlight-fg, declared in both the html[data-theme='light'] and html[data-theme='dark'] blocks alongside --highlight and --selected. Everything else in those rules (radius, box-decoration-break) stays as-is.

src/app.css declares the classic family in the existing :root block, next to the two tokens already there.

The URL split is not taken. No --highlight-url / --search-hit-url-* tokens are declared, so URL hits keep rendering exactly like title hits. The kind prop and the .search-hit.url rules from §4.2 are still built — that is what makes the split a one-line addition later — but they resolve through the fallback to the title tokens, so this ships as a no-op for URLs.

Contrast check — one pair ships below AA. Per the criterion in §6, every ink/background pair was measured against the signed-off values:
PairLightDark
Hit ink on hit background (the criterion)13.84:1 ✅11.69:1 ✅
Title on selected row10.90:1 ✅7.06:1 ✅
URL / breadcrumb (--sub) on selected row3.44:1 ⚠️ (was 4.41:1)2.63:1 ⚠️ (was 3.43:1)

Accepted, with the reason: the new selection greens are deliberately bolder, which costs contrast for the muted --sub ink used by the URL line and breadcrumb on the selected row only. Dark was already under AA here (3.43:1) and gets worse; light drops under for the first time. This affects secondary metadata on a single transient row, not the title or the hits, and --sub is out of scope for this ticket. If it should be fixed instead of accepted, the cheap remedy is a dedicated --sub-on-selected ink rather than walking the greens back — file it as a follow-up.

Gamut: all six modern values convert cleanly into sRGB with no channel clipping, so the rendered colour matches the number written. Light --highlight resolves to #ffd501 and --selected to #83e283; dark resolves to #ecc411 and #265a28.

6. Acceptance criteria

  • The five-role token family from §4.1 exists for both looks: classic tokens in src/app.css :root, modern tokens declared in both the html[data-theme='light'] and html[data-theme='dark'] blocks of ModernView.svelte.
  • No highlight or selection color is written as a literal inside a rule any more — in particular .search-hit's color: oklch(0.15 0 0) is gone, replaced by var(--highlight-fg).
  • A hit inside a URL can be styled independently of a hit inside a title, in both looks, via the URL tokens; when those tokens are absent the URL hit renders identically to a title hit (fallback chain in §4.2).
  • The committed values are exactly the nine in the §5.1 table, character for character — four of them change what ships, the rest are the current values restated as tokens. No other colour moves.
  • The URL tokens are not declared (§5.1): a URL hit renders identically to a title hit through the fallback chain, in both looks. Removing the URL tokens from the output is not the same as removing the kind plumbing, which still ships.
  • Hit ink on its hit background meets WCAG AA (4.5:1) in every theme that ships — measured at 13.84:1 light and 11.69:1 dark. The one pair below AA (--sub on a selected row) is the known, accepted exception documented in §5.1 and must be repeated in the build PR description.
  • Highlighting behaviour is unchanged: same segments matched, same box-decoration-break: clone on multi-line matches, same 2px radius, no layout shift (no padding added to .search-hit).
  • Both looks still render correctly with the modern theme setting on System, Light and Dark, and switching theme on the options page updates an open popup live (existing chrome.storage.onChanged path).
  • npm run check and npm run build pass in bookmark-express-v3/.

8. Out of scope & open questions

  • Out of scope — a shared palette file. Classic keeps its tokens in app.css, modern keeps its oklch palette inside ModernView.svelte. Merging the two into one theme module is a worthwhile cleanup and a separate ticket.
  • Out of scope — a user-facing setting for highlight color. These stay build-time tokens.
  • Resolved — classic keeps today's colors and stays single-scheme. Its values are unchanged in §5.1; it gains only --search-hit-fg: inherit, which restates the current behaviour as a token. A dark variant for classic, and the gray-on-yellow URL hit it would fix (3.68:1 today), are not addressed here — worth a follow-up ticket.
  • Resolved — the selected-row colors do move. Both modern greens were retuned along with the hit swatches, since the two are judged as a pair. This is the source of the accepted contrast exception in §5.1.
  • Follow-up candidate — --sub on a selected row. A dedicated ink for secondary metadata on the selected row would clear AA in both themes without touching the greens just agreed. Out of scope here; see §5.1.
